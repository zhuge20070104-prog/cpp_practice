# Spark Structured Streaming 窗口函数详解

## 窗口函数语法

```python
func.window(func.col("eventTime"), "30 seconds", "10 seconds")
```

### 参数说明

- **第一个参数**: `func.col("eventTime")` - 时间戳列，用于窗口分组
- **第二个参数**: `"30 seconds"` - **窗口大小（Window Duration）**
- **第三个参数**: `"10 seconds"` - **滑动间隔（Slide Duration）**

---

## 详细解释

### 窗口大小（30 seconds）

**窗口大小**定义了每个时间窗口覆盖的时间范围。在本例中，每个窗口覆盖 **30 秒**的数据。

### 滑动间隔（10 seconds）

**滑动间隔**定义了多久创建一个新窗口。在本例中，每隔 **10 秒**就会创建一个新的 30 秒窗口。

### 关键特性：窗口重叠

因为窗口大小（30秒）大于滑动间隔（10秒），所以**窗口会重叠**，这意味着同一个事件可能会出现在多个窗口中。

---

## 具体例子

假设我们从 `12:00:00` 开始接收数据：

### 时间轴示意

```
时间点:     12:00:00  12:00:10  12:00:20  12:00:30  12:00:40  12:00:50  12:01:00
           |---------|---------|---------|---------|---------|---------|
           
窗口1:     [====== 30秒 ======]
           12:00:00 → 12:00:30

窗口2:               [====== 30秒 ======]
                     12:00:10 → 12:00:40

窗口3:                         [====== 30秒 ======]
                               12:00:20 → 12:00:50

窗口4:                                   [====== 30秒 ======]
                                         12:00:30 → 12:01:00
```

### 数据流示例

假设有以下 HTTP 访问日志事件：

```
12:00:05 - 访问 /home
12:00:15 - 访问 /about
12:00:25 - 访问 /home
12:00:35 - 访问 /home
12:00:45 - 访问 /contact
```

### 每个窗口包含的数据

| 窗口 | 时间范围 | 包含的事件 | /home 计数 | /about 计数 | /contact 计数 |
|------|----------|-----------|-----------|------------|--------------|
| **窗口1** | 12:00:00 - 12:00:30 | ① /home (12:00:05)<br>② /about (12:00:15)<br>③ /home (12:00:25) | **2** | **1** | **0** |
| **窗口2** | 12:00:10 - 12:00:40 | ② /about (12:00:15)<br>③ /home (12:00:25)<br>④ /home (12:00:35) | **2** | **1** | **0** |
| **窗口3** | 12:00:20 - 12:00:50 | ③ /home (12:00:25)<br>④ /home (12:00:35)<br>⑤ /contact (12:00:45) | **2** | **0** | **1** |
| **窗口4** | 12:00:30 - 12:01:00 | ④ /home (12:00:35)<br>⑤ /contact (12:00:45) | **1** | **0** | **1** |

### 关键观察

1. **12:00:25 的 /home 访问**出现在 **窗口1、窗口2 和 窗口3** 中
2. **12:00:35 的 /home 访问**出现在 **窗口2、窗口3 和 窗口4** 中
3. 每个事件最多可以出现在 **3 个窗口**中（30秒 ÷ 10秒 = 3）

## 窗口类型对比

### 滑动窗口（Sliding Window）- 当前使用

```python
func.window(col("eventTime"), "30 seconds", "10 seconds")
```

- 窗口大小：30 秒
- 滑动间隔：10 秒
- **窗口重叠**：是
- 数据重复计算：同一事件在多个窗口中

### 滚动窗口（Tumbling Window）

```python
func.window(col("eventTime"), "30 seconds", "30 seconds")
# 或简写为
func.window(col("eventTime"), "30 seconds")
```

- 窗口大小：30 秒
- 滑动间隔：30 秒（等于窗口大小）
- **窗口重叠**：否
- 数据重复计算：每个事件只在一个窗口中

**滚动窗口示意**：
```
窗口1: [12:00:00 - 12:00:30]
窗口2:                      [12:00:30 - 12:01:00]
窗口3:                                          [12:01:00 - 12:01:30]
       没有重叠 ↑
```

---

## 使用场景

### 滑动窗口（30秒窗口，10秒滑动）适用于：

1. **平滑的趋势分析**：获得更平滑的指标变化曲线
2. **实时监控**：更频繁的更新（每10秒）
3. **异常检测**：捕捉短期突发流量
4. **热门内容追踪**：如本例中的热门 URL 统计

### 滚动窗口（30秒窗口，30秒滑动）适用于：

1. **精确统计**：每个事件只计算一次
2. **报表生成**：按时间段汇总数据
3. **资源优化**：更少的计算开销

## 代码中的实际效果

在 `top-urls.py` 中：

```python
endpointCounts = logsDF2.groupBy(
    func.window(func.col("eventTime"), "30 seconds", "10 seconds"), 
    func.col("endpoint")
).count()
```

**这段代码的作用**：
- 每 **10 秒**生成一个新的统计结果
- 每个统计结果包含过去 **30 秒**的数据
- 统计每个 endpoint（URL 路径）的访问次数
- 结果按访问次数降序排列，显示最热门的 URL

**输出示例**：

|{2025-11-10 12:00:10, 2025-11-10 12:00:40}|/home     |18   |

## 性能考虑

### 优点
- ✅ 更平滑的实时分析
- ✅ 更快的响应时间（每10秒更新）
- ✅ 可以捕捉短期趋势

### 缺点
- ⚠️ 更多的计算开销（数据重复处理）
- ⚠️ 更高的内存使用（需要维护多个窗口的状态）
- ⚠️ 输出数据量更大

---

## 调整建议

### 如果想要更频繁的更新：
```python
func.window(col("eventTime"), "30 seconds", "5 seconds")  # 每5秒更新
```

### 如果想要更长的时间跨度：
```python
func.window(col("eventTime"), "5 minutes", "1 minute")  # 5分钟窗口，每分钟更新
```

### 如果想要避免重叠：
```python
func.window(col("eventTime"), "30 seconds")  # 滚动窗口，无重叠
```

---

## 总结

在 `func.window(col("eventTime"), "30 seconds", "10 seconds")` 中：

- **30 seconds**（窗口大小）= 每个窗口覆盖 30 秒的数据
- **10 seconds**（滑动间隔）= 每 10 秒创建一个新窗口
- **重叠度** = 30 ÷ 10 = 3（每个事件最多出现在 3 个窗口中）

这种配置实现了**滑动窗口**分析，能够提供更平滑、更频繁的实时统计结果，非常适合监控和追踪热门内容的场景。
