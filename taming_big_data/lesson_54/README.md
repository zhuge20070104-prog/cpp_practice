# MovieSimilarities1M - 基于 RDD 的电影相似度计算

## 概述

这个脚本使用 Apache Spark 的 RDD API 来计算电影之间的相似度。它通过分析用户的评分数据，找出哪些电影经常被相同的用户以相似的方式评价，从而推荐相似的电影。

## RDD 结构变换详解

本文档详细解释脚本中每一步的 RDD 结构变换，通过具体例子展示数据如何一步步转换。

---

### 示例数据

假设我们有 3 个用户对几部电影的评分：

| 用户ID | 电影ID | 评分 |
|--------|--------|------|
| 1      | 1193   | 5.0  |
| 1      | 661    | 3.0  |
| 1      | 914    | 3.0  |
| 2      | 1193   | 4.0  |
| 2      | 661    | 5.0  |
| 3      | 914    | 5.0  |

---

## 第 1 步：读取原始数据

```python
data = sc.textFile("s3n://sundog-spark/ml-1m/ratings.dat")
```

**RDD 结构：** 每个元素是一个字符串

```
"1::1193::5::978300760"
"1::661::3::978302109"
"1::914::3::978301968"
"2::1193::4::978298413"
"2::661::5::978297878"
"3::914::5::978299215"
```

**数据格式：** `用户ID::电影ID::评分::时间戳`

---

## 第 2 步：解析并映射为 (用户ID, (电影ID, 评分))

```python
ratings = data.map(lambda l: l.split("::")).map(lambda l: (int(l[0]), (int(l[1]), float(l[2]))))
```

**RDD 结构：** `(用户ID, (电影ID, 评分))`

```python
(1, (1193, 5.0))  # 用户1给电影1193评分5.0
(1, (661, 3.0))   # 用户1给电影661评分3.0
(1, (914, 3.0))   # 用户1给电影914评分3.0
(2, (1193, 4.0))  # 用户2给电影1193评分4.0
(2, (661, 5.0))   # 用户2给电影661评分5.0
(3, (914, 5.0))   # 用户3给电影914评分5.0
```

**转换说明：**
- 第一个 `map`：将字符串按 `::` 分割成数组
- 第二个 `map`：提取用户ID、电影ID和评分，并转换为合适的类型
- **键（Key）**：用户ID
- **值（Value）**：(电影ID, 评分) 元组

---

## 第 3 步：分区并自连接（Self-Join）

```python
ratingsPartitioned = ratings.partitionBy(100)
joinedRatings = ratingsPartitioned.join(ratingsPartitioned)
```

**关键操作：** 自连接会将同一个用户的所有电影评分进行笛卡尔积组合

**RDD 结构：** `(用户ID, ((电影ID1, 评分1), (电影ID2, 评分2)))`

```python
# 用户1的所有电影组合（3个电影会产生3×3=9个组合）
(1, ((1193, 5.0), (1193, 5.0)))  # 电影1193和自己
(1, ((1193, 5.0), (661, 3.0)))   # 电影1193和661的组合
(1, ((1193, 5.0), (914, 3.0)))   # 电影1193和914的组合
(1, ((661, 3.0), (1193, 5.0)))   # 电影661和1193的组合
(1, ((661, 3.0), (661, 3.0)))    # 电影661和自己
(1, ((661, 3.0), (914, 3.0)))    # 电影661和914的组合
(1, ((914, 3.0), (1193, 5.0)))   # 电影914和1193的组合
(1, ((914, 3.0), (661, 3.0)))    # 电影914和661的组合
(1, ((914, 3.0), (914, 3.0)))    # 电影914和自己

# 用户2的所有电影组合（2个电影会产生2×2=4个组合）
(2, ((1193, 4.0), (1193, 4.0)))
(2, ((1193, 4.0), (661, 5.0)))
(2, ((661, 5.0), (1193, 4.0)))
(2, ((661, 5.0), (661, 5.0)))

# 用户3只评了1个电影，所以只有1个组合
(3, ((914, 5.0), (914, 5.0)))
```

**转换说明：**
- `partitionBy(100)`：将数据分成100个分区，提高并行度
- `join`：自连接操作，将相同键（用户ID）的值进行配对
- 如果用户评了 N 部电影，会生成 N×N 个组合

---

## 第 4 步：过滤重复对

```python
uniqueJoinedRatings = joinedRatings.filter(filterDuplicates)

def filterDuplicates(userRatings):
    ratings = userRatings[1]
    (movie1, rating1) = ratings[0]
    (movie2, rating2) = ratings[1]
    return movie1 < movie2
```

**目的：** 
1. 去除同一电影和自己的配对（如 `(1193, 1193)`）
2. 去除重复的配对（保留 `(661, 1193)` 而去除 `(1193, 661)`）

**RDD 结构：** 只保留 `movie1 < movie2` 的配对

```python
# 用户1的组合（过滤后剩3个）
(1, ((661, 3.0), (1193, 5.0)))   # 661 < 1193 ✓
(1, ((661, 3.0), (914, 3.0)))    # 661 < 914 ✓
(1, ((914, 3.0), (1193, 5.0)))   # 914 < 1193 ✓

# 用户2的组合（过滤后剩1个）
(2, ((661, 5.0), (1193, 4.0)))   # 661 < 1193 ✓

# 用户3没有有效组合（只有一个电影）
```

**过滤效果：**
- 用户1：9个组合 → 3个有效组合
- 用户2：4个组合 → 1个有效组合

---

## 第 5 步：转换键为电影对

```python
moviePairs = uniqueJoinedRatings.map(makePairs).partitionBy(100)

def makePairs(userRatings):
    ratings = userRatings[1]
    (movie1, rating1) = ratings[0]
    (movie2, rating2) = ratings[1]
    return ((movie1, movie2), (rating1, rating2))
```

**关键变化：** 从"用户视角"转换为"电影对视角"

**RDD 结构：** `((电影ID1, 电影ID2), (评分1, 评分2))`

```python
((661, 1193), (3.0, 5.0))  # 用户1对这两部电影的评分
((661, 914), (3.0, 3.0))   # 用户1对这两部电影的评分
((914, 1193), (3.0, 5.0))  # 用户1对这两部电影的评分
((661, 1193), (5.0, 4.0))  # 用户2对这两部电影的评分
```

**转换说明：**
- **新的键（Key）**：电影对 `(电影ID1, 电影ID2)`
- **新的值（Value）**：对应的评分对 `(评分1, 评分2)`
- 这一步是关键转换，为后续聚合做准备

---

## 第 6 步：按电影对分组

```python
moviePairRatings = moviePairs.groupByKey()
```

**关键操作：** 将相同电影对的所有评分对收集在一起

**RDD 结构：** `((电影ID1, 电影ID2), [(评分1, 评分2), (评分1, 评分2), ...])`

```python
# 电影661和1193这一对，被用户1和用户2都评过
((661, 1193), [(3.0, 5.0), (5.0, 4.0)])

# 电影661和914这一对，只被用户1评过
((661, 914), [(3.0, 3.0)])

# 电影914和1193这一对，只被用户1评过
((914, 1193), [(3.0, 5.0)])
```

**聚合效果：**
- 相同的电影对作为同一个键
- 所有共同评价过这对电影的用户的评分被收集到一个列表中
- 这个列表就是计算相似度的基础数据

---

## 第 7 步：计算余弦相似度

```python
moviePairSimilarities = moviePairRatings.mapValues(computeCosineSimilarity).persist()
```

**计算公式：** 余弦相似度

$$
\text{similarity} = \frac{\sum_{i} (rating_{1i} \times rating_{2i})}{\sqrt{\sum_{i} rating_{1i}^2} \times \sqrt{\sum_{i} rating_{2i}^2}}
$$

**计算示例：** 电影 661 和 1193

评分对：`[(3.0, 5.0), (5.0, 4.0)]`

```python
sum_xx = 3.0*3.0 + 5.0*5.0 = 9 + 25 = 34
sum_yy = 5.0*5.0 + 4.0*4.0 = 25 + 16 = 41
sum_xy = 3.0*5.0 + 5.0*4.0 = 15 + 20 = 35
numPairs = 2

score = 35 / (sqrt(34) * sqrt(41)) 
      = 35 / 37.336 
      ≈ 0.937
```

**RDD 结构：** `((电影ID1, 电影ID2), (相似度得分, 共同评分数))`

```python
((661, 1193), (0.937, 2))    # 相似度0.937，有2个用户同时评了这两部电影
((661, 914), (1.0, 1))       # 相似度1.0，有1个用户评了这两部电影
((914, 1193), (0.857, 1))    # 相似度0.857，有1个用户评了这两部电影
```

**返回值说明：**
- **相似度得分**：范围 [0, 1]，越接近 1 表示越相似
- **共同评分数**：有多少用户同时评价了这两部电影（样本大小）

---

## 第 8 步：过滤和排序（推荐相似电影）

```python
if (len(sys.argv) > 1):
    scoreThreshold = 0.97
    coOccurenceThreshold = 50
    
    movieID = int(sys.argv[1])
    
    # 过滤出与目标电影相似且满足质量阈值的电影
    filteredResults = moviePairSimilarities.filter(lambda pairSim: \
        (pairSim[0][0] == movieID or pairSim[0][1] == movieID) \
        and pairSim[1][0] > scoreThreshold and pairSim[1][1] > coOccurenceThreshold)
    
    # 按相似度得分排序
    results = filteredResults.map(lambda pairSim: (pairSim[1], pairSim[0])).sortByKey(ascending = False).take(10)
```

**过滤条件：**
1. 电影对中包含目标电影ID
2. 相似度得分 > 0.97（高相似度）
3. 共同评分数 > 50（足够的样本支持）

**示例：** 查询电影 1193 的相似电影

```python
# 原始数据
((661, 1193), (0.937, 2))   # 不满足相似度阈值 0.937 < 0.97，被过滤 ✗
((914, 1193), (0.857, 1))   # 不满足相似度和样本数阈值，被过滤 ✗

# 假设还有其他满足条件的电影
((1193, 858), (0.98, 65))   # ✓ 满足所有条件
((260, 1193), (0.99, 102))  # ✓ 满足所有条件
((1193, 527), (0.985, 78))  # ✓ 满足所有条件
```

**反转键值并排序：**

```python
# 将 ((电影对), (相似度, 数量)) 转换为 ((相似度, 数量), (电影对))
((0.99, 102), (260, 1193))   # 最高相似度，排第一
((0.985, 78), (1193, 527))   # 第二
((0.98, 65), (1193, 858))    # 第三
```

**输出格式：**

```
Top 10 similar movies for Star Wars: Episode IV - A New Hope (1977)
The Empire Strikes Back (1980)         score: 0.99    strength: 102
Return of the Jedi (1983)              score: 0.985   strength: 78
Raiders of the Lost Ark (1981)         score: 0.98    strength: 65
```

## 核心算法流程图

```
原始数据（用户::电影::评分）
    ↓
(用户ID, (电影ID, 评分))              [按用户分组]
    ↓
(用户ID, ((电影A, 评分A), (电影B, 评分B)))  [自连接：找同一用户评的电影对]
    ↓
过滤重复和自身配对                      [只保留 A < B]
    ↓
((电影A, 电影B), (评分A, 评分B))        [转换为电影对视角]
    ↓
((电影A, 电影B), [(评分对1), (评分对2), ...])  [聚合相同电影对]
    ↓
((电影A, 电影B), (相似度, 样本数))      [计算余弦相似度]
    ↓
过滤 + 排序 + 输出前10                  [推荐相似电影]
```

## 关键优化技术

### 1. **partitionBy(100)**
```python
ratingsPartitioned = ratings.partitionBy(100)
moviePairs = uniqueJoinedRatings.map(makePairs).partitionBy(100)
```
- 将数据分成 100 个分区
- 提高并行处理能力
- 在 join 和 groupByKey 操作前分区可以减少数据传输

### 2. **persist()**
```python
moviePairSimilarities = moviePairRatings.mapValues(computeCosineSimilarity).persist()
```
- 将计算结果缓存在内存中
- 后续多次使用时（保存文件 + 过滤查询）不需要重新计算

### 3. **filterDuplicates**
- 在自连接后立即过滤，减少后续处理的数据量
- 9 个组合 → 3 个有效组合（减少 67% 数据）

## 数学原理：余弦相似度

**余弦相似度** 衡量两个向量在方向上的相似程度，不考虑大小。

### 为什么使用余弦相似度？

假设两部电影：
- 电影A：被所有用户评为 5 分（高评分用户群）
- 电影B：被所有用户评为 3 分（严格评分用户群）

虽然绝对分数不同，但评分**模式相似**（都被同样的用户喜欢），余弦相似度能捕捉这种模式相似性。

### 计算步骤

1. **点积（Dot Product）**：`sum_xy = Σ(ratingA × ratingB)`
2. **向量长度**：
   - `|A| = sqrt(Σ(ratingA²))`
   - `|B| = sqrt(Σ(ratingB²))`
3. **余弦相似度**：`cos(θ) = sum_xy / (|A| × |B|)`

**结果范围：** [0, 1]（因为评分都是正数）
- 1.0 = 完全相似
- 0.5 = 中等相似
- 0.0 = 完全不相似

## 总结

这个脚本展示了 Spark RDD 的强大转换能力：

1. **视角转换**：从"用户-电影"关系转换为"电影-电影"关系
2. **分布式计算**：通过 join、groupByKey 等操作处理大规模数据
3. **协同过滤**：基于用户行为（评分）发现电影间的隐含关系
4. **质量控制**：通过相似度阈值和样本数阈值确保推荐质量

**核心思想：** 如果两部电影经常被相同的用户以相似的方式评价，那么它们很可能是相似的电影。
